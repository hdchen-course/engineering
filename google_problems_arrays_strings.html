Arrays & Strings — Google-style Problems

Note: Representative big-tech-style problems — not sourced from Google. The “Google-style” badge denotes the flavor of question, not its source.

Plus One

Easy Google-style

Problem

A non-negative integer is stored as an array of decimal digits, most-significant digit first, with no leading zeros (the number 0 is the single-element array [0]). Add one to this number and return the resulting digit array.

  • Digits are in the range 0..9; the array has at least one element.
  • The result may be one digit longer than the input (for example, 999 + 1 = 1000).

Example: [2, 4, 9] represents 249, so the answer is [2, 5, 0]. And [9, 9] becomes [1, 0, 0].

Approach & Intuition

This is primary-school addition with a single seeded carry. Start with carry = 1 (that is the "+1") and sweep the digits from right to left. At each position add the carry, keep the ones digit in place, and push any tens digit left. If a carry survives past the leftmost digit, the number overflowed to a new power of ten (e.g. 99 → 100), so allocate one extra slot and place the leading 1.

// Treat the array as one big number, most-significant digit first.
// Seed carry = 1 (the "+1"), then ripple it right-to-left.
public int[] plusOne(int[] digits) {
    int n = digits.length, carry = 1;
    for (int i = n - 1; 0 <= i; --i) {   // walk from the last digit backwards
        int sum = digits[i] + carry;
        digits[i] = sum % 10;                 // keep the ones digit in place
        carry = sum / 10;                     // 0 or 1 propagates left
    }
    if (0 == carry) return digits;         // no overflow: array is already correct
    // Overflow (e.g. 999 -> 1000): need one extra leading slot.
    int[] res = new int[n + 1];
    res[0] = carry;                          // the new leading 1
    for (int i = 0; i < n; ++i) res[i + 1] = digits[i];
    return res;
}

Complexity: Time O(n) (single pass, plus an O(n) copy only on overflow). Space O(1) extra when there is no carry-out, otherwise O(n) for the one-longer result array.

Common pitfalls / interviewer probes: (1) Forgetting the all-nines overflow case, which is the only time the length changes. (2) Trying to convert the array to an int/long first — it overflows for large inputs; that is exactly why the problem uses a digit array. (3) Expect a follow-up on "add two big-integer arrays" or a different base — the same right-to-left carry loop generalizes directly.

Valid Parentheses

Easy Google-style

Problem

Given a string containing only the six bracket characters (), [], and {}, decide whether the brackets are balanced. A string is balanced when every closing bracket matches the most recently opened, still-unclosed bracket of the same type, and no bracket is left open.

  • The string may be empty (empty counts as valid).
  • Order matters: ([)] is invalid even though counts match.

Example: "{[]}" is valid, "(]" is invalid, and "((" is invalid (two openers never close).

Approach & Intuition

Bracket nesting is last-opened-first-closed, which is exactly a stack. Push every opener. On a closer, the top of the stack must be the matching opener — if the stack is empty or the top is the wrong type, fail fast. At the end the stack must be empty, otherwise some opener never closed.

public boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();   // used as a LIFO stack
    for (char c : s.toCharArray()) {
        if (c == ')') { if (stack.isEmpty() || stack.pollLast() != '(') return false; }
        else if (c == ']') { if (stack.isEmpty() || stack.pollLast() != '[') return false; }
        else if (c == '}') { if (stack.isEmpty() || stack.pollLast() != '{') return false; }
        else stack.addLast(c);                       // an opener: push it
    }
    return stack.isEmpty();                          // leftover openers => invalid
}

Complexity: Time O(n), one pass over the string. Space O(n) for the stack in the worst case (all openers).

Common pitfalls / interviewer probes: (1) Forgetting the empty-stack check on a closer — pollLast() on an empty deque returns null and the string like ")" is misjudged. (2) Forgetting the final isEmpty() check, which is what rejects "((". (3) Watch Character auto-unboxing: comparing a possibly-null boxed value with == against a char can NPE, so the empty check must come first (short-circuit || guarantees it). A common follow-up generalizes to arbitrary bracket pairs via a map, or asks for the count of characters to remove/insert to make it valid.

Container With Most Water

Medium Google-style

Problem

You are given an array of non-negative heights, where each value is a vertical line drawn at that index. Picking two lines and the x-axis forms a container. Its water capacity equals the shorter of the two lines multiplied by the horizontal distance between them. Return the maximum capacity over all pairs.

  • At least two lines are given.
  • The container is not slanted; only the two chosen lines bound the water — inner lines are ignored.

Example: for heights [3, 9, 2, 6, 7, 4, 8] the best pair is the 9 at index 1 and the 8 at index 6: area = min(9, 8) × (6 - 1) = 40.

Approach & Intuition

Start with the widest possible container: one pointer at each end. The area is capped by the shorter wall, so the width is as large as it will ever be for that shorter wall — moving the taller wall inward can only reduce width without lifting the cap, so it can never help. Therefore always move the shorter wall inward, hunting for a taller one, and track the best area seen. This linear sweep provably examines the optimum.

public int maxArea(int[] h) {
    int i = 0, j = h.length - 1, best = 0;   // widest container first
    while (i < j) {
        // Area is bounded by the shorter wall; move THAT wall inward.
        // (j-- - i) and (j - i++) compute the width BEFORE the pointer moves.
        if (h[i] >= h[j]) best = Math.max(best, h[j] * (j-- - i));
        else            best = Math.max(best, h[i] * (j - i++));
    }
    return best;
}

Complexity: Time O(n) — the two pointers move toward each other and meet once. Space O(1).

Common pitfalls / interviewer probes: (1) The greedy move must be on the shorter wall; moving the taller one is the classic wrong choice — be ready to justify why the shorter wall can be safely discarded. (2) When the two walls are equal, moving either is fine (this code moves j); the discarded equal wall cannot be part of a strictly larger area. (3) Do not confuse this with Trapping Rain Water — here inner lines are ignored and you want one maximal container, not total trapped volume. (4) Watch the post-increment/decrement in the width expression; a common bug computes the width after the pointer already moved.

Trapping Rain Water

Hard Google-style

Problem

An elevation map is given as an array of non-negative bar heights, each bar one unit wide. After rain, water pools in the valleys. Return the total units of water trapped between the bars.

  • Water above index x rises to min(highest bar to its left, highest bar to its right), minus the bar's own height (never negative).
  • The array may be empty or have a single bar (both trap zero).

Example: [2, 0, 3, 1, 0, 2, 1] traps 5 units; [5, 1, 0, 2, 4] traps 9.

Approach & Intuition

The water level over any position is set by the lower of the tallest walls on its two sides. Use two pointers from the ends. Whichever side currently has the lower outer wall is the guaranteed bottleneck for that side, so fix that wall as the water level and advance inward, adding level - height for every shorter bar until a taller bar appears (which becomes the new limiter). Because the opposite wall is known to be at least as tall, the level is safe. This runs in one linear pass without precomputing prefix/suffix maxima.

public int trap(int[] h) {
    int i = 0, j = h.length - 1, water = 0;
    while (i < j) {
        // The lower of the two outer walls fixes the water level on its side.
        if (h[i] >= h[j]) {
            int level = h[j];                          // right wall is the limiter
            while (i < j && h[j] <= level) water += level - h[j--];
        } else {
            int level = h[i];                          // left wall is the limiter
            while (i < j && h[i] <= level) water += level - h[i++];
        }
    }
    return water;
}

Complexity: Time O(n) — every index is consumed by exactly one pointer. Space O(1).

Common pitfalls / interviewer probes: (1) The correctness hinges on always working from the shorter outer wall; if you fix the taller side you can over- or under-count. (2) Empty and single-element arrays must return 0 (the i < j guard handles them). (3) Interviewers often ask for the trade-offs between this O(1)-space two-pointer method, the prefix/suffix-max arrays version (O(n) space, arguably easier to reason about), and a monotonic-stack solution that adds water layer by layer. (4) A frequent follow-up is the 2D version ("Trapping Rain Water II"), which needs a min-heap boundary sweep rather than two pointers.

3Sum

Medium Google-style

Problem

Given an integer array, return every distinct triple of values that sums to zero. Two triples are the same if they contain the same three values regardless of order, and each distinct triple must appear only once in the output.

  • The array may contain duplicates and negative numbers.
  • Fewer than three elements yields an empty result.

Example: for [-3, 1, 2, -1, -1, 4, 0] the answer is [[-3, -1, 4], [-3, 1, 2], [-1, -1, 2], [-1, 0, 1]]. For [0, 0, 0, 0] it is just [[0, 0, 0]].

Approach & Intuition

Sort the array so that duplicates sit together and a two-pointer scan becomes possible. Fix each value as the anchor i, then find pairs in the suffix that sum to -nums[i] by walking a left pointer up and a right pointer down. The sum monotonically responds to pointer moves: too small → move left up, too big → move right down. Deduplicate at three levels — skip repeated anchors, and after recording a hit skip repeated left/right values — so each distinct triple is emitted exactly once.

public List<List<Integer>> threeSum(int[] nums) {
    List<List<Integer>> res = new ArrayList<>();
    if (nums == null || nums.length < 3) return res;
    int n = nums.length;
    Arrays.sort(nums);                                // enables two pointers + easy dedup
    for (int i = 0; i + 2 < n; ++i) {
        if (i != 0 && nums[i] == nums[i - 1]) continue;   // skip duplicate anchors
        if (nums[i] > 0) break;                          // smallest is positive: no zero-sum left
        int j = i + 1, k = n - 1;
        while (j < k) {
            int sum = nums[i] + nums[j] + nums[k];
            if (sum == 0) {
                res.add(Arrays.asList(nums[i], nums[j], nums[k]));
                while (j < k && nums[j] == nums[j + 1]) j++;   // skip dup left values
                while (j < k && nums[k] == nums[k - 1]) k--;   // skip dup right values
                j++; k--;
            } else if (sum > 0) k--;                     // too big: shrink from the right
            else j++;                                     // too small: grow from the left
        }
    }
    return res;
}

Complexity: Time O(n log n) for the sort plus O(n2) for the anchored two-pointer scans → O(n2) overall. Space O(1) beyond the sort and the output list (O(log n)–O(n) for the sort's internals).

Common pitfalls / interviewer probes: (1) The single most common bug is incomplete deduplication — you must skip duplicate anchors and skip duplicate left/right values after a hit; doing only one produces repeated triples. (2) A hash-set-of-triples approach also works but costs more memory and still needs care; the sorted two-pointer method is the expected answer. (3) The nums[i] > 0 early break is a safe optimization on sorted input, not required for correctness. (4) Interviewers commonly extend to 4Sum / kSum (recurse down to a two-pointer base case) or "3Sum Closest," which drops the dedup but tracks the sum nearest a target.

Next Permutation

Medium Google-style

Problem

Given an array of numbers representing one arrangement, rearrange it in place into the next arrangement in lexicographic (dictionary) order. If the array is already the largest arrangement (fully descending), wrap around to the smallest (fully ascending). Only constant extra memory may be used.

  • Values may repeat; ordering is by value.
  • A single element (or empty input) is its own next permutation.

Example: [2, 3, 1] → [3, 1, 2]; [1, 4, 4] → [4, 1, 4]; and the largest, [5, 4, 2] → [2, 4, 5] (wrap-around).

Approach & Intuition

Scan from the right to find the first "pivot" — the last position where nums[i-1] < nums[i]. Everything to its right is a non-increasing tail that is already at its maximum, so it cannot advance without raising the pivot. Swap the pivot with the smallest value to its right that is still larger than it (found by scanning the tail from the right). That makes the prefix the next-larger prefix; the tail is still descending, so reverse it to the smallest order. If no pivot exists, the whole array is descending — reverse it entirely to wrap to the smallest permutation.

public void nextPermutation(int[] nums) {
    if (nums == null || nums.length <= 1) return;   // empty or single element: already its own next permutation
    int n = nums.length, i = n - 1, j = i;
    // 1) find pivot: walk left while the tail is non-increasing
    while (0 < i && nums[i - 1] >= nums[i]) i--;
    if (0 == i) {                          // whole array descending: wrap to ascending
        while (i < j) swap(nums, i++, j--);
        return;
    }
    i--;                                    // i is now the pivot index (nums[i] < nums[i+1])
    // 2) find rightmost value greater than the pivot
    while (i < j && nums[i] >= nums[j]) j--;
    swap(nums, i++, j);                      // 3) swap, then advance i to the tail start
    // 4) reverse the (still descending) tail into ascending order
    j = n - 1;
    while (i < j) swap(nums, i++, j--);
}

private void swap(int[] a, int i, int j) {
    int t = a[i]; a[i] = a[j]; a[j] = t;
}

Complexity: Time O(n) — at most three linear passes (find pivot, find successor, reverse tail). Space O(1), fully in place.

Common pitfalls / interviewer probes: (1) The pivot comparison must use >= so that equal values in the tail are treated as non-increasing; using > breaks on inputs with duplicates. (2) Do not forget the reverse step — after swapping, the tail is descending and must be flipped to ascending, otherwise you skip permutations. (3) The all-descending / wrap-around case is the classic missed edge; a single element must also be handled. (4) A tempting XOR-swap trick is a hidden trap: swapping an element with itself via XOR zeroes it out, so prefer the plain temp-variable swap shown here — interviewers read the plain temp as cleaner. Expect a follow-up asking for the k-th permutation or the previous permutation (mirror the comparisons).

Rotate Image

Medium Google-style

Problem

You are given an n × n grid of integers. Turn the whole grid a quarter-turn clockwise so that the top row becomes the right-hand column, and do it in place — you may not allocate a second grid to copy into.

  • The matrix is square (1 ≤ n ≤ 20 or so); cell values are arbitrary 32-bit integers, possibly negative or duplicated.
  • Extra memory must be O(1) beyond the input.

Example: starting from [[2,7,1],[9,4,3],[6,8,5]], a clockwise quarter-turn yields [[6,9,2],[8,4,7],[5,3,1]] — the first row 6,9,2 is the old first column read bottom-up.

Approach & Intuition

A clockwise 90° rotation factors into two cheap in-place passes. First transpose (mirror across the main diagonal, swapping a[i][j] with a[j][i]); this turns rows into columns. Then reverse every row left-to-right. The composition lands each element exactly where the rotation wants it, using only swaps — no scratch matrix.

// Rotate an n x n matrix 90 degrees clockwise, in place.
// Step 1: transpose across the main diagonal.
// Step 2: reverse each row.
static void rotate(int[][] matrix) {
    if (matrix == null || matrix.length == 0) return;   // defensive: empty / null
    int m = matrix.length;

    // --- transpose: swap the upper triangle with the lower triangle ---
    for (int i = 0; i < m; ++i) {
        for (int j = i + 1; j < m; ++j) {   // j starts at i+1, so we touch each pair once
            int tmp = matrix[i][j];
            matrix[i][j] = matrix[j][i];
            matrix[j][i] = tmp;
        }
    }

    // --- reverse every row in place with a two-pointer sweep ---
    for (int i = 0; i < m; ++i) {
        int j = 0, k = m - 1;
        while (j < k) {
            // plain temp swap: clear and has no aliasing hazard
            int tmp = matrix[i][j];
            matrix[i][j] = matrix[i][k];
            matrix[i][k] = tmp;
            j++; k--;
        }
    }
}

Complexity: Time O(n²) — each cell is touched a constant number of times. Space O(1) — only swaps, no auxiliary grid.

Common pitfalls / interviewer probes: Direction confusion — transpose-then-reverse-rows gives clockwise; for counter-clockwise you transpose then reverse the columns (or reverse rows first). State which one you're building. Double-swap bug — if the transpose loop runs j from 0 instead of i+1, every pair is swapped twice and you get the original matrix back. Use a plain temp swap — a clever XOR swap (a^=b;b^=a;a^=b;) silently zeroes a cell when the two indices coincide, so the straightforward temp swap used here is both safe and clearer. A frequent follow-up: rotate a rectangular m×n matrix (no longer in place) or rotate by an arbitrary multiple of 90°.

Multiply Strings

Medium Google-style

Problem

Two non-negative integers are given as decimal strings num1 and num2 (they may be far larger than any built-in integer type). Return their product, again as a string. You may not convert the inputs to a native integer or rely on a big-integer library.

  • 1 ≤ length ≤ 200; each string is digits only, with no leading zeros except the literal "0".
  • The answer must likewise carry no extra leading zeros.

Example: "327" × "89" = "29103"; and "0" × "74" = "0".

Approach & Intuition

Multiplying an m-digit number by an n-digit number produces at most m + n digits. Allocate an int[m+n] accumulator. The product of num1[i] and num2[j] lands in exactly two buckets: the units digit at index i+j+1 and the carry at index i+j. Add each partial product into those buckets and normalise the carry immediately. Finally, skip leading zero buckets and stitch the digits into a string.

// Multiply two non-negative decimal strings without native bignum.
static String multiply(String num1, String num2) {
    char[] cs1 = num1.toCharArray(), cs2 = num2.toCharArray();
    int m = cs1.length, n = cs2.length;
    int[] nums = new int[m + n];               // product has at most m+n digits

    for (int i = m - 1; 0 <= i; --i) {
        for (int j = n - 1; 0 <= j; --j) {
            int prod = (cs1[i] - '0') * (cs2[j] - '0');
            nums[i + j + 1] += prod;           // add into the "units" slot for this pair
            nums[i + j]     += nums[i + j + 1] / 10;  // spill the carry left
            nums[i + j + 1] %= 10;             // keep only a single digit here
        }
    }

    // skip leading zeros; if everything is zero the answer is "0"
    int i = 0;
    while (i < nums.length && nums[i] == 0) i++;
    if (i == nums.length) return "0";

    StringBuilder sb = new StringBuilder();
    while (i < nums.length) sb.append(nums[i++]);
    return sb.toString();
}

Complexity: Time O(m·n) — every digit pair is multiplied once. Space O(m+n) for the accumulator.

Common pitfalls / interviewer probes: The index mapping is the whole trick — a pair (i, j) contributes its ones digit to position i+j+1 and its carry to i+j. Off-by-one here is the #1 bug. Carry propagation — because nums[i+j+1] can exceed 9 after accumulation, you must divide-then-mod in the shown order; doing the carry before adding the partial product loses digits. Leading-zero cleanup — forgetting the skip leaves answers like "056088", and forgetting the all-zero guard returns an empty string for "0"×"0". Why no overflow — each bucket holds a single-digit product plus a bounded carry, so a 32-bit int never overflows even for 200-digit inputs (a common probe). Follow-ups: add two strings, or generalise to an arbitrary base.

Longest Substring Without Repeating Characters

Medium Google-style

Problem

Given a string s, find the length of the longest contiguous block that contains no repeated character.

  • 0 ≤ length ≤ 10⁵; characters may be letters, digits, symbols, or spaces.
  • Aim for a single linear pass.
  • Charset note: the int[256] table assumes single-byte (extended-ASCII / Latin-1) code points; for arbitrary Unicode, swap it for a HashMap<Character,Integer>.

Example: in "abcadef" the best window is "bcadef", length 6. In "kkkk" it is just "k", length 1.

Approach & Intuition

Keep a window (start, i] that is always duplicate-free. Store, for each character code, the last index at which it appeared. When the current character was seen inside the window, jump start forward to just past that earlier occurrence. Because start is the index before the window begins, the current window length is simply i - start. We only ever move start forward, so it stays a true single-pass window.

// Longest run of distinct characters. 'start' is the index just LEFT of
// the current window, so window length == i - start.
static int lengthOfLongestSubstring(String s) {
    int[] last = new int[256];      // last[c] = last index where char c was seen
    java.util.Arrays.fill(last, -1);
    int start = -1, best = 0;

    for (int i = 0; i < s.length(); ++i) {
        int c = s.charAt(i);
        if (last[c] != -1) {
            // if the previous sighting is inside the window, shrink from the left.
            // max() guards against an OLD sighting that is already left of start.
            start = Math.max(start, last[c]);
        }
        best = Math.max(best, i - start);
        last[c] = i;                // record current position
    }
    return best;
}

Complexity: Time O(length) — one pass, each index visited once. Space O(1) for a fixed 256-entry table (independent of input size).

Common pitfalls / interviewer probes: The max() is essential — for input like "abba", when the second a arrives its last-seen index sits behind the already-advanced start; without start = max(start, last[c]) you would wrongly pull the window backward and count a duplicate b. Charset size — a 256-slot array covers extended ASCII; if the interviewer says "full Unicode," switch to a HashMap<Character,Integer>. Length formula — tracking start as the slot before the window keeps it i - start (no +1); mixing this up with the "start = first index of window" convention causes off-by-one errors. Probes: return the substring itself, or the count of distinct-char substrings.

Longest Substring with At Most Two Distinct Characters

Medium Google-style

Problem

Given a string s, return the length of the longest contiguous block that uses at most two distinct characters.

  • 0 ≤ length ≤ 10⁵; input is ASCII.
  • Linear time is expected.
  • Charset note: the int[128] frequency table assumes ASCII code points; for arbitrary Unicode, swap it for a HashMap<Character,Integer>.

Example: in "abaccc" the best window is "accc" (only a and c), length 4. In "xxyyzzz" it is "yyzzz", length 5.

Approach & Intuition

Expand the right edge one character at a time, maintaining a frequency table and a live count of how many distinct characters the window holds. The moment that count reaches three, shrink from the left — decrementing frequencies — until it drops back to two. After each step the window is valid, so record its length. Each index enters and leaves the window at most once, giving a linear scan.

// Longest window containing at most two distinct characters.
static int lengthOfLongestSubstringTwoDistinct(String s) {
    char[] cs = s.toCharArray();
    int[] freq = new int[128];      // frequency of each char inside the window
    int max = 0, start = 0, n = cs.length, distinct = 0;

    for (int i = 0; i < n; ++i) {
        if (freq[cs[i]]++ == 0) distinct++;   // a brand-new character entered
        while (distinct == 3) {               // too many kinds: shrink from left
            if (--freq[cs[start++]] == 0) distinct--;
        }
        max = Math.max(max, i - start + 1);
    }
    return max;
}

Complexity: Time O(length) — left and right pointers each advance monotonically. Space O(1) (fixed 128-entry table).

Common pitfalls / interviewer probes: Shrink on the RIGHT threshold — the window is legal at two distinct, so you only shrink once a third kind appears (distinct == 3); shrinking at == 2 is a classic mistake. Track the count, not the map size, per step — incrementing distinct only when a frequency rises from 0, and decrementing only when it falls back to 0, avoids re-scanning the table. Empty string — the loop never runs and it correctly returns 0. The key follow-up is generalisation to k distinct — replace the constant 3 with k+1 and, for large/unknown alphabets, swap the array for a HashMap; this is a common follow-up.

Minimum Window Substring

Hard Google-style

Problem

Given a string s and a pattern t, return the shortest contiguous slice of s that contains every character of t including duplicates (order does not matter). If no such slice exists, return the empty string.

  • 1 ≤ |s|, |t| ≤ 10⁵; the answer is guaranteed unique when it exists.
  • Target linear time.
  • Charset note: the two int[128] tables assume ASCII code points; for arbitrary Unicode, swap them for a HashMap<Character,Integer>.

Example: for s = "ADCFEBA", t = "ABC", the shortest covering window is "CFEBA" (uniquely — no other length-5 window covers t). If t = "ABCC" (two Cs needed but only one exists), the answer is "".

Approach & Intuition

Tally how many of each character t requires, and a single integer count = how many still-unmet character slots remain. Advance the right edge; each time you consume a character the window genuinely still needed, decrement count. When count hits zero the window is a valid cover — now advance the left edge as far as possible, recording the smallest cover, and stop shrinking the instant removing a character breaks coverage (its need count climbs back above zero).

// Shortest window of s that contains all chars of t (with multiplicity).
static String minWindow(String s, String t) {
    if (s == null || t == null || t.length() == 0) return "";
    boolean[] needed = new boolean[128];   // is this char part of t?
    int[] need = new int[128];             // how many of this char still required
    int best = Integer.MAX_VALUE, i = 0, j = 0, start = 0, count = 0;

    for (char c : t.toCharArray()) { needed[c] = true; need[c]++; count++; }

    char[] cs = s.toCharArray();
    while (i < cs.length) {
        if (count > 0) {
            need[cs[i]]--;
            // only chars t wants, while still "in deficit", reduce the count
            if (needed[cs[i]] && need[cs[i]] >= 0) count--;
        }
        while (count == 0) {                 // window [j, i] covers t
            if (best > i - j + 1) { best = i - j + 1; start = j; }
            need[cs[j]]++;
            // if we just removed a NEEDED char below the requirement, break coverage
            if (needed[cs[j]] && need[cs[j]] > 0) count++;
            j++;
        }
        i++;
    }
    return best == Integer.MAX_VALUE ? "" : s.substring(start, start + best);
}

Complexity: Time O(|s| + |t|) — each pointer crosses s once. Space O(1) (two fixed 128-entry tables).

Common pitfalls / interviewer probes: Duplicates in t matter — a Set is wrong; you must count multiplicities, so t = "aa" demands two as. The >= 0 vs > 0 asymmetry — when expanding, a needed char reduces count only while its remaining need was still non-negative (surplus copies don't help); when contracting, coverage breaks only when a needed char's requirement goes back strictly positive. Getting these boundaries backwards is the most common bug. Characters outside t get their need pushed negative and are freely shrunk away — that is intended. Empty/oversized t — guard t empty, and any window can't be smaller than |t|. Follow-ups: window with exactly the multiset, or the same idea over a stream where you can't index backward.

Backspace String Compare

Easy Google-style

Problem

Two strings s and t are typed into an editor where '#' means "backspace" (delete the character before it; on empty text it does nothing). Decide whether the two, once fully applied, produce the same final text.

  • 1 ≤ length ≤ 200; lowercase letters plus '#'.
  • The interesting version asks for O(1) extra space (no rebuilt strings).

Example: s = "xy#z" becomes "xz"; t = "xw#z" also becomes "xz" → equal. But "m#n" (→ "n") and "p" differ.

Approach & Intuition

Rebuilding both strings costs O(n) space; instead walk backwards from both ends. A '#' seen while scanning right-to-left means "skip the next real character," so carry a skip tally: each '#' increments it, and each real character is consumed (not compared) while skip > 0. When both scans land on a surviving character, compare them. Do this until both pointers fall off the left end.

// Compare two "typed" strings under '#' = backspace, using O(1) space.
static boolean backspaceCompare(String s, String t) {
    char[] cs = s.toCharArray(), ct = t.toCharArray();
    int i = cs.length - 1, j = ct.length - 1;

    while (i >= 0 || j >= 0) {
        // advance i to the next surviving character in s
        int skip = 0;
        while (i >= 0) {
            if (cs[i] == '#') { i--; skip++; }        // a backspace: owe one deletion
            else if (skip > 0) { skip--; i--; }       // this char is deleted
            else break;                               // a genuine surviving char
        }
        // advance j to the next surviving character in t
        skip = 0;
        while (j >= 0) {
            if (ct[j] == '#') { j--; skip++; }
            else if (skip > 0) { skip--; j--; }
            else break;
        }
        // compare the two survivors
        if (i >= 0 && j >= 0 && cs[i] != ct[j]) return false;
        if ((i >= 0) != (j >= 0)) return false;        // one ran out before the other
        i--; j--;
    }
    return true;
}

Complexity: Time O(|s| + |t|) — each character visited once. Space O(1) — no rebuilt buffers, just two indices and a counter.

Common pitfalls / interviewer probes: Why scan backwards — a backspace affects characters to its left, so a right-to-left walk lets you resolve deletions locally without a stack; the O(n)-space stack/rebuild solution is the easy warm-up and the reverse scan is the "can you do O(1) space?" follow-up. The length-mismatch check is easy to forget — (i >= 0) != (j >= 0) catches the case where one string has a surviving character while the other is exhausted; e.g. "a#c" vs "c" must stay equal, but "ac" vs "c" must not. Leading backspaces are no-ops — "#" and "" both reduce to empty. Don't compare while skip > 0 — consume first, compare only true survivors. Probe: report the resulting strings, or handle it as a live keystroke stream.
