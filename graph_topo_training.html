BFS & DFS

BFS Template (Level-order, shortest path in unweighted)

Queue<Integer> queue = new LinkedList<>();
boolean[] visited = new boolean[n];
int[] dist = new int[n];        // dist[i] = edges from start to i
queue.offer(start);
visited[start] = true;
dist[start] = 0;
int level = 0;

while (!queue.isEmpty()) {
    int size = queue.size();
    for (int i = 0; i < size; i++) {
        int node = queue.poll();
        for (int neighbor : graph.get(node)) {
            if (!visited[neighbor]) {
                visited[neighbor] = true;
                dist[neighbor] = dist[node] + 1;   // = level + 1: shortest hop count
                queue.offer(neighbor);
            }
        }
    }
    level++;                       // dist[] now holds shortest distances from start
}

DFS Template (Iterative)

Deque<Integer> stack = new ArrayDeque<>();
boolean[] visited = new boolean[n];
stack.push(start);

while (!stack.isEmpty()) {
    int node = stack.pop();
    if (visited[node]) continue;
    visited[node] = true;
    for (int neighbor : graph.get(node))
        if (!visited[neighbor])
            stack.push(neighbor);
}

Start BFS from ALL sources simultaneously (add all to queue at level 0). Used for: "minimum distance from any source" problems like 01-Matrix, Rotting Oranges.

Topological Sort

Linear ordering of vertices in a DAG such that for every edge u→v, u comes before v. Only exists if graph has no cycles.

Intuition First: Just Keep Peeling Off the "Ready" Tasks

Forget algorithms for a second. Imagine getting dressed. Some rules are fixed: socks before shoes, shirt before jacket, underwear before pants. Nobody hands you the full order. So how do you actually do it? You look for anything with no unmet prerequisite — something you can put on right now — and you put it on. Socks? Nothing needed first, put them on. Underwear? Same, put it on. Now shoes and pants just became "ready" because their blockers are gone. Repeat until you're dressed. The order you peel things off is a valid topological order.

That is the entire idea, and it maps perfectly onto course prerequisites: a course is "takeable" the moment every prerequisite is already taken. Keep taking takeable courses; the sequence you take them in is a topo order.

The one mechanical rule: repeatedly remove any node whose in-degree is 0 (no arrows pointing into it = no unmet prerequisites). When you remove it, erase its outgoing arrows — that may drop other nodes to in-degree 0, making them ready next. The removal order is the answer. That mechanical rule is literally Kahn's algorithm below.

Tiny worked example (do it by hand in 15 seconds). Tasks with arrows meaning "must come first": A→C, B→C, C→D. In-degrees: A=0, B=0, C=2, D=1. Ready now: {A, B}. Peel A → erase A→C, now C=1. Peel B → erase B→C, now C=0 (ready!). Peel C → erase C→D, now D=0. Peel D. Order peeled: A, B, C, D — a valid topo order. (A, B were interchangeable, so B, A, C, D is equally valid.)

When to Use

Signal words: "prerequisite", "dependency", "ordering", "schedule", "before/after"
Key insight: If the problem involves ordering with constraints (A must come before B), it's topological sort.

Method 1: Kahn's Algorithm (BFS-based) — PREFERRED

// O(V + E) — also detects cycles (if result.size() < n, cycle exists)
int[] topoSort(int n, List<List<Integer>> graph) {
    int[] indegree = new int[n];
    for (int u = 0; u < n; u++)
        for (int v : graph.get(u))
            indegree[v]++;

    Queue<Integer> queue = new LinkedList<>();
    for (int i = 0; i < n; i++)
        if (indegree[i] == 0) queue.offer(i);

    int[] order = new int[n];
    int idx = 0;

    while (!queue.isEmpty()) {
        int u = queue.poll();
        order[idx++] = u;
        for (int v : graph.get(u)) {
            indegree[v]--;
            if (indegree[v] == 0) queue.offer(v);
        }
    }

    return idx == n ? order : new int[0];  // empty = cycle
}

The code, mapped to the "peeling" picture

indegree[v]++Count arrows pointing into each node = how many prerequisites it still has.
if (indegree[i]==0) queue.offer(i)Seed: every node that starts "ready" (no prereqs) goes into the queue.
u = queue.poll(); order[idx++]=uPeel a ready node and append it to the output order.
indegree[v]--Erase u's outgoing arrows: each neighbor loses one prerequisite.
if (indegree[v]==0) queue.offer(v)A neighbor just became ready — it can be peeled next.
return idx==n ? order : ...If we peeled fewer than n nodes, some nodes were never ready → a cycle exists (see below).

Method 2: DFS-based (Post-order reverse)

boolean[] visited = new boolean[n];
boolean[] inStack = new boolean[n];  // for cycle detection
Deque<Integer> stack = new ArrayDeque<>();
boolean hasCycle = false;

void dfs(int u) {
    visited[u] = true;
    inStack[u] = true;
    for (int v : graph.get(u)) {
        if (inStack[v]) { hasCycle = true; return; }
        if (!visited[v]) dfs(v);
        if (hasCycle) return;  // abort: propagate the cycle up, discard partial stack
    }
    inStack[u] = false;
    stack.push(u);  // post-order
}

// Call dfs for all unvisited nodes, then stack = topo order

Why reversing finish-times works (the key "aha")

DFS explores as deep as it can, then backtracks. A node finishes (we run out of edges to explore from it) only after every node it can reach has already finished. So if u→v, then v always finishes before u. Push each node onto a stack the moment it finishes, and the last-finished (which must be a "source") ends up on top. Popping the stack — i.e. reading finish-times in reverse — therefore emits every u before its descendants: a valid topo order.

visited[u]=true; inStack[u]=trueMark u seen, and mark it on the current recursion path (for cycle detection).
if (inStack[v]) hasCycle=trueAn edge back to a node still on the path = back edge = cycle.
if (!visited[v]) dfs(v)Recurse into unexplored children first (go deep).
inStack[u]=false; stack.push(u)u is finished (all descendants done) → push it. Later pops give reverse-finish = topo order.

Cycle Detection Falls Out for Free

Topo sort and cycle detection are the same computation. A cycle is a set of tasks that all wait on each other — a deadlock — so no valid ordering can exist. Both methods notice this automatically:

  • Kahn's: if you finish the loop but peeled fewer than n nodes (idx < n), the leftovers are the nodes on a cycle together with any node reachable from one — their in-degree never reached 0 because each is directly or transitively waiting on a cycle member.
  • DFS: if you ever hit an edge u→v where v is still on the current recursion stack (inStack[v] == true, the "GRAY" state), that's a back edge — you've looped back onto your own path, which is a cycle.

Variant: Detect if Unique Topo Order Exists

In Kahn's algorithm, if at any point the queue has more than one element, multiple valid orderings exist (the order is NOT unique).

Variant: Longest Path in DAG

// Process nodes in topological order, relax edges
int[] dist = new int[n];
Arrays.fill(dist, Integer.MIN_VALUE);
dist[source] = 0;

for (int u : topoOrder) {
    if (dist[u] == Integer.MIN_VALUE) continue;
    for (int[] edge : graph.get(u)) {
        int v = edge[0], w = edge[1];
        dist[v] = Math.max(dist[v], dist[u] + w);
    }
}

Variant: All Topological Orders (Backtracking)

// Used when problem asks "all valid orderings"
void allTopoSort(List<Integer> current) {
    if (current.size() == n) { result.add(new ArrayList<>(current)); return; }
    for (int i = 0; i < n; i++) {
        if (!visited[i] && indegree[i] == 0) {
            visited[i] = true;
            current.add(i);
            for (int v : graph.get(i)) indegree[v]--;
            allTopoSort(current);
            for (int v : graph.get(i)) indegree[v]++;
            current.remove(current.size() - 1);
            visited[i] = false;
        }
    }
}

Interview Framing

How to recognize it in ~20 seconds: the problem gives you pairwise "must-come-before" constraints and asks for a valid total order (or just "is one possible?"). Reword any such problem as "build a DAG where an edge A→B means A must precede B, then topo-sort." If the answer is "impossible / can't be done," they're really asking you to detect a cycle.

What to say out loud: (1) "I'll model this as a directed graph." (2) "The ordering constraint makes it a topo-sort." (3) "I'll use Kahn's / BFS in-degree — O(V+E), and it doubles as cycle detection since a leftover node means a cycle." (4) State whether the ordering must be unique or lexicographically smallest (swap the queue for a PriorityQueue).

Classic Application 2: Alien Dictionary (LC 269)

Given words sorted in an unknown alphabet's order, recover a valid letter order. The twist that trips people up: the edges aren't given — you derive them. Compare each adjacent pair of words; the first differing character gives one ordering edge c1→c2. Then it's a plain topo sort over the letters.

// For adjacent words w1, w2: find first index where they differ.
for (int i = 0; i < Math.min(w1.length(), w2.length()); i++) {
    char a = w1.charAt(i), b = w2.charAt(i);
    // graph.get(a) is a Set: only count the edge if it's newly added (avoid double-counting indegree).
    if (a != b) { if (graph.get(a).add(b)) indegree[b]++; break; }  // a -> b, then STOP
}
// Edge case: w2 is a PREFIX of w1 but w1 is LONGER (e.g. "abc" before "ab") -> invalid input.
// Then run Kahn's over the 26 letters; a cycle means "no valid order".

Two classic Alien Dictionary traps: (1) only the first differing char yields an edge — break immediately after adding it. (2) If w1 is longer than w2 but w2 is a prefix of w1 ("abc" then "ab"), the input is invalid — return "".

Dijkstra Template

int[] dijkstra(int n, List<List<int[]>> graph, int src) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;

    // {distance, node}
    PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> Integer.compare(a[0], b[0]));
    pq.offer(new int[]{0, src});

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], u = curr[1];
        if (d > dist[u]) continue;  // stale entry
        for (int[] edge : graph.get(u)) {
            int v = edge[0], w = edge[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                pq.offer(new int[]{dist[v], v});
            }
        }
    }
    return dist;
}

Bellman-Ford (handles negative edges, K-stop limit)

// LC 787 Cheapest Flights Within K Stops
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);
dist[src] = 0;

for (int i = 0; i <= k; i++) {
    int[] prev = dist.clone();  // prevent using current round
    for (int[] edge : edges) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (prev[u] != Integer.MAX_VALUE)
            dist[v] = Math.min(dist[v], prev[u] + w);
    }
}

Two flavors, don't confuse them: the prev = dist.clone() per round is only needed for the K-stop constraint (LC 787) — it stops a value updated this round from cascading through more than one extra edge. Plain shortest-path Bellman-Ford drops the clone and relaxes all edges in place for exactly V-1 rounds; if any edge still relaxes on round V, a negative cycle is reachable. For K stops, allowing at most K intermediate stops means at most K+1 edges, hence the loop runs k+1 times (i = 0..k).

Floyd-Warshall (All-Pairs Shortest Paths)

Computes shortest paths between ALL pairs of nodes. O(V³) — only use when V ≤ 400 and you need all-pairs distances.

Key idea: "Can going through node k improve the shortest path from i to j?" Try every intermediate node k in the outer loop. The loop order MUST be k → i → j (not i → j → k).

// Floyd-Warshall: dist[i][j] = shortest path from i to j
int INF = Integer.MAX_VALUE / 2;
int[][] dist = new int[n][n];
for (int[] row : dist) Arrays.fill(row, INF);
for (int i = 0; i < n; i++) dist[i][i] = 0;
for (int[] e : edges) dist[e[0]][e[1]] = e[2]; // or min if multiple edges

// THE core triple loop — k MUST be outermost
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            dist[i][j] = Math.min(dist[i][j], dist[i][k] + dist[k][j]);

Common bug: Using Integer.MAX_VALUE directly causes overflow when adding dist[i][k] + dist[k][j]. Use MAX_VALUE / 2 or check for INF before adding.

Floyd Variants

  • Transitive closure: Replace min with OR, weights with boolean reachability. reach[i][j] |= reach[i][k] && reach[k][j]
  • Minimax path: Replace min(dist[i][j], dist[i][k] + dist[k][j]) with min(dist[i][j], max(dist[i][k], dist[k][j]))
  • Count shortest paths: Maintain parallel count[i][j] array
  • Path reconstruction: Store next[i][j] = k when improving, trace recursively

Union-Find (Disjoint Set Union)

Template with Path Compression + Union by Rank

class UnionFind {
    int[] parent, rank;
    int components;

    UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        components = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        if (parent[x] != x)
            parent[x] = find(parent[x]);  // path compression
        return parent[x];
    }

    boolean union(int x, int y) {
        int px = find(x), py = find(y);
        if (px == py) return false;
        if (rank[px] < rank[py]) { int t = px; px = py; py = t; }
        parent[py] = px;
        if (rank[px] == rank[py]) rank[px]++;
        components--;
        return true;
    }
}

When to Use

Dynamic connectivity: "are x and y connected?"
Count components as edges are added
Detect cycle in undirected graph: if union returns false
Kruskal's MST: sort edges + union-find

Minimum Spanning Tree

Kruskal's (Edge-based): O(E log E)

// Sort edges by weight, greedily add if no cycle
Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));
UnionFind uf = new UnionFind(n);
int mstWeight = 0, edgeCount = 0;

for (int[] edge : edges) {
    if (uf.union(edge[0], edge[1])) {
        mstWeight += edge[2];
        if (++edgeCount == n - 1) break;
    }
}

Prim's (Vertex-based): O((V+E) log V)

// Start from any vertex, greedily pick cheapest edge to new vertex
PriorityQueue<int[]> pq = new PriorityQueue<>((a,b) -> Integer.compare(a[1], b[1]));
boolean[] inMST = new boolean[n];
pq.offer(new int[]{0, 0});  // {node, weight}

while (!pq.isEmpty()) {
    int[] curr = pq.poll();
    int u = curr[0], w = curr[1];
    if (inMST[u]) continue;
    inMST[u] = true;
    mstWeight += w;
    for (int[] edge : graph.get(u))
        if (!inMST[edge[0]])
            pq.offer(new int[]{edge[0], edge[1]});
}

Cycle Detection

Directed Graph: DFS with 3-color marking

// WHITE=0 (unvisited), GRAY=1 (in current path), BLACK=2 (done)
int[] color = new int[n];

boolean hasCycle(int u) {
    color[u] = 1;  // GRAY
    for (int v : graph.get(u)) {
        if (color[v] == 1) return true;  // back edge!
        if (color[v] == 0 && hasCycle(v)) return true;
    }
    color[u] = 2;  // BLACK
    return false;
}

Undirected Graph: Union-Find or DFS with parent tracking

// Union-Find: if union(u, v) returns false, edge creates cycle
for (int[] edge : edges) {
    if (!uf.union(edge[0], edge[1]))
        return edge;  // this edge creates cycle
}

Bipartite Graph

A graph whose vertices can be divided into two disjoint sets such that every edge connects a vertex in one set to a vertex in the other.

Check Bipartite: BFS 2-coloring

boolean isBipartite(int[][] graph) {
    int n = graph.length;
    int[] color = new int[n];  // 0=unvisited, 1=red, -1=blue

    for (int i = 0; i < n; i++) {
        if (color[i] != 0) continue;
        Queue<Integer> queue = new LinkedList<>();
        queue.offer(i);
        color[i] = 1;
        while (!queue.isEmpty()) {
            int u = queue.poll();
            for (int v : graph[u]) {
                if (color[v] == 0) {
                    color[v] = -color[u];
                    queue.offer(v);
                } else if (color[v] == color[u]) {
                    return false;  // odd cycle
                }
            }
        }
    }
    return true;
}

Key Insight

A graph is bipartite if and only if it contains no odd-length cycle. 2-coloring BFS is the standard check.

Strongly Connected Components & Bridges

Tarjan's Algorithm for Bridges (Cut Edges)

int timer = 0;
int[] disc, low;  // disc = new int[n]; Arrays.fill(disc, -1) BEFORE dfs — Java's default 0 would look "visited"
List<int[]> bridges = new ArrayList<>();

// Run dfs(i, -1) for every i with disc[i] == -1 to cover disconnected graphs.
void dfs(int u, int parent) {
    disc[u] = low[u] = timer++;
    for (int v : graph.get(u)) {
        if (v == parent) continue;
        if (disc[v] == -1) {
            dfs(v, u);
            low[u] = Math.min(low[u], low[v]);
            if (low[v] > disc[u])
                bridges.add(new int[]{u, v});  // bridge!
        } else {
            low[u] = Math.min(low[u], disc[v]);
        }
    }
}

disc vs low: disc[u] = when u was discovered (its DFS order); low[u] = the disc of the earliest ancestor this subtree can climb back to. The bridge test low[v] > disc[u] means: v's entire subtree, apart from the edge u→v, has no back edge that loops back to u or any ancestor above u → removing that edge disconnects the graph. Use disc[v] for a back edge (its landing point), because a back edge jumps to an ancestor in one step and stops there — it cannot climb further up.

Parallel-edge trap: the if (v == parent) continue; shortcut skips all edges back to the parent, so it is wrong when the graph has a multi-edge (two edges between the same pair) — that pair is never a bridge, yet this code would report one. To be safe, skip by edge id (pass the id used to arrive, and continue only on that exact edge) instead of by vertex. LC 1192 guarantees no duplicate edges, so the vertex check is fine there, but state this assumption out loud in an interview.

Kosaraju's SCC (2-pass DFS)

Intuition: If we process nodes in reverse finish-time order on the reversed graph, each DFS tree we encounter is exactly one SCC. This works because a node finished late in pass 1 is a "root" of its SCC — reversing edges ensures its SCC members are only reachable from it, not from other SCCs.

// Kosaraju's Algorithm — returns list of SCCs
List<List<Integer>> kosaraju(int n, List<List<Integer>> graph) {
    // Pass 1: DFS on original graph, record finish order
    boolean[] visited = new boolean[n];
    Deque<Integer> finishOrder = new ArrayDeque<>();

    for (int i = 0; i < n; i++)
        if (!visited[i]) dfs1(i, graph, visited, finishOrder);

    // Build reversed graph
    List<List<Integer>> rev = new ArrayList<>();
    for (int i = 0; i < n; i++) rev.add(new ArrayList<>());
    for (int u = 0; u < n; u++)
        for (int v : graph.get(u)) rev.get(v).add(u);

    // Pass 2: DFS on reversed graph in reverse finish order
    Arrays.fill(visited, false);
    List<List<Integer>> sccs = new ArrayList<>();
    while (!finishOrder.isEmpty()) {
        int node = finishOrder.pop();
        if (!visited[node]) {
            List<Integer> scc = new ArrayList<>();
            dfs2(node, rev, visited, scc);
            sccs.add(scc);
        }
    }
    return sccs;
}

void dfs1(int u, List<List<Integer>> g, boolean[] vis, Deque<Integer> order) {
    vis[u] = true;
    for (int v : g.get(u)) if (!vis[v]) dfs1(v, g, vis, order);
    order.push(u); // record finish time
}

void dfs2(int u, List<List<Integer>> g, boolean[] vis, List<Integer> scc) {
    vis[u] = true;
    scc.add(u);
    for (int v : g.get(u)) if (!vis[v]) dfs2(v, g, vis, scc);
}

Tarjan's SCC (single-pass, stack-based)

Intuition: Maintain a stack of "currently in progress" nodes. A node is the root of its SCC if low[u] == disc[u] — meaning no node in its subtree can reach anything earlier. Pop everything above it from the stack = one SCC.

// Tarjan's SCC Algorithm
int timer = 0;
int[] disc, low, comp; // comp[u] = which SCC node u belongs to
boolean[] onStack;
Deque<Integer> stack = new ArrayDeque<>();
int numSCC = 0;

void tarjanSCC(int u) {
    disc[u] = low[u] = timer++;
    stack.push(u);
    onStack[u] = true;

    for (int v : graph.get(u)) {
        if (disc[v] == -1) {
            tarjanSCC(v);
            low[u] = Math.min(low[u], low[v]);
        } else if (onStack[v]) {
            low[u] = Math.min(low[u], disc[v]);
        }
    }

    // If u is root of an SCC
    if (low[u] == disc[u]) {
        while (true) {
            int v = stack.pop();
            onStack[v] = false;
            comp[v] = numSCC;
            if (v == u) break;
        }
        numSCC++;
    }
}

Euler Path / Circuit

What is it?

An Euler path visits every EDGE exactly once. An Euler circuit is an Euler path that starts and ends at the same vertex. (Contrast with Hamiltonian path which visits every VERTEX once — that's NP-hard.)

Existence Conditions

DirectedEvery vertex has in-degree = out-degree AND graph is strongly connectedAt most one vertex has out-in=1 (start), at most one has in-out=1 (end) AND connected ignoring edge direction

Hierholzer's Algorithm (Euler Circuit/Path)

Key idea: DFS but remove edges as you traverse them. When you get stuck (no more edges from current node), add current node to the result and backtrack. The result (reversed) is the Euler path. This is NOT regular DFS — you must delete edges to avoid reuse.

// Hierholzer's for DIRECTED graph (LC 332 Reconstruct Itinerary)
Map<String, PriorityQueue<String>> graph = new HashMap<>();
List<String> result = new ArrayList<>();

void dfs(String node) {
    PriorityQueue<String> neighbors = graph.get(node);
    while (neighbors != null && !neighbors.isEmpty()) {
        String next = neighbors.poll();  // remove edge (use it up)
        dfs(next);
    }
    result.add(node);  // add to front when "stuck"
}

// Call: dfs(startNode); Collections.reverse(result);

// For UNDIRECTED graph — mark edges as used (need edge IDs)
void hierholzerUndirected(int start) {
    Deque<Integer> stack = new ArrayDeque<>();
    List<Integer> path = new ArrayList<>();
    stack.push(start);
    while (!stack.isEmpty()) {
        int u = stack.peek();
        if (hasUnusedEdge(u)) {
            int[] edge = getNextUnusedEdge(u);
            markUsed(edge);
            stack.push(edge[1]); // go to other endpoint
        } else {
            path.add(stack.pop()); // backtrack: add to result
        }
    }
    Collections.reverse(path);
}

Common interview disguise: "Reconstruct Itinerary" (LC 332) = Euler path on directed multigraph. "Cracking the Safe" (LC 753) = Euler circuit on de Bruijn graph. Recognize these as Euler problems and Hierholzer's follows naturally.

Real-world uses

  • Chinese Postman Problem (mail delivery visiting every street)
  • DNA sequencing (Euler path on de Bruijn graph of k-mers)
  • Drawing puzzles ("draw without lifting your pen")

A* Search

What is it?

Informed search that uses a heuristic to guide exploration. Like Dijkstra, but instead of expanding the node with smallest g(n) (cost so far), it expands the node with smallest f(n) = g(n) + h(n) where h(n) estimates remaining cost to goal.

When is it useful?

  • Games: pathfinding on maps (characters navigating obstacles)
  • Grid problems: when BFS is too slow and you have a natural distance heuristic
  • State-space search: sliding puzzles, Rubik's cube
  • Interviews: rare, but LC 1197 (Minimum Knight Moves) can use it

Key Property: Admissibility

h(n) must be admissible: it never OVERestimates the true remaining cost. If admissible, A* finds the optimal path. Common heuristics: Manhattan distance (grid, 4-directional), Euclidean distance (continuous), Chebyshev distance (8-directional).

// A* Search Template
int aStar(int[][] grid, int[] start, int[] goal) {
    int n = grid.length, m = grid[0].length;
    int[][] dist = new int[n][m];
    for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
    dist[start[0]][start[1]] = 0;

    // PQ ordered by f = g + h
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[2], b[2]));
    int h = heuristic(start, goal);
    pq.offer(new int[]{start[0], start[1], h}); // {row, col, f}

    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};
    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int r = curr[0], c = curr[1];
        if (r == goal[0] && c == goal[1]) return dist[r][c];
        if (curr[2] > dist[r][c] + heuristic(new int[]{r,c}, goal)) continue;

        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nr >= n || nc < 0 || nc >= m) continue;
            int newDist = dist[r][c] + grid[nr][nc]; // edge cost
            if (newDist < dist[nr][nc]) {
                dist[nr][nc] = newDist;
                pq.offer(new int[]{nr, nc, newDist + heuristic(new int[]{nr,nc}, goal)});
            }
        }
    }
    return -1;
}

int heuristic(int[] a, int[] b) {
    return Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]); // Manhattan
}

AlgorithmWhen to useExplores
BFSUnweighted, guaranteed shortestAll nodes at distance d before d+1
DijkstraWeighted, no heuristic availableExpands by cheapest g(n)
A*Weighted, good heuristic availableExpands by cheapest g(n) + h(n) → fewer nodes explored

Interview context: If asked "how to speed up Dijkstra on a grid?", mention A* with Manhattan heuristic. In practice, A* explores far fewer nodes when the heuristic is tight. For LC problems, BFS/Dijkstra usually suffice — A* is more of a system design / game dev topic.
