How to Recognize a DP Problem

Code examples are in Java. Quick syntax key: 1<<n = bit-shift, & = bitwise-AND, Deque = double-ended queue — see the Java Refresher for syntax.

Two Core Properties

  1. Optimal Substructure — The optimal solution can be constructed from optimal solutions of its subproblems.
  2. Overlapping Subproblems — The same subproblem is solved multiple times during recursion.

Quick Signal Words

High probability DP when you see: "minimum", "maximum", "longest", "shortest", "number of ways", "is it possible", "count all", "optimal cost under constraint"

Decision Tree

Q1: Does the problem ask to enumerate ALL permutations/combinations? └— Yes → Backtracking (not DP) └— No → Q2: Does it have Optimal Substructure? (answer = f(sub-answers)) └— No → Greedy / BFS / Other └— Yes → Q3: Do subproblems overlap? └— No → Divide & Conquer └— Yes → Dynamic Programming

The 5-Step DP Framework

1. Define State — What does dp[i] represent? Say it in one sentence.
2. Transition — How to compute dp[i] from smaller subproblems?
3. Base Case — What are the trivial sub-answers?
4. Computation Order — Bottom-up or Top-down? Ensure dependencies are met.
5. Answer Location — Is the final answer dp[n]? dp[n][m]? max(dp[...])?

How to INVENT a DP (a repeatable recipe)

The lie people tell about DP: "just spot the overlapping subproblems." Sometimes that's true. But often the hard part is modeling — deciding what a subproblem even is. That step can feel like magic ("if you don't see it, you never will"). It isn't. There is a mechanical procedure that manufactures the recurrence for the large majority of DP problems. Run it every time and DP stops being a lottery.

The whole trick in one line: a DP is just brute-force recursion where you (1) name the choice, (2) name the smaller thing left after the choice, and (3) stop re-solving the same smaller thing. The recurrence writes itself once you can name those pieces.

The 7-step recipe

  1. Find the decision. At each step, what am I choosing? (Take/skip this item? Which coin? Where to cut? Which element goes next?) List the concrete options.
  2. Look at the LAST decision. Ask: "If I imagine the optimal solution already built, what was the final choice, and what does the problem look like after undoing it?" That leftover is a smaller instance of the same problem. (Thinking about the last step, not the first, is what keeps the leftover self-similar.)
  3. Define the STATE. The state is the minimal set of facts you need to describe that leftover subproblem — nothing about how you got there. Quick test: "If I told a fresh solver only these numbers, could they finish the job?" If yes, the state is complete; if they'd ask a follow-up question, that question is the missing dimension.
  4. Write the recurrence. Always the same shape:
    answer(state) = best over choices of ( cost(choice) + answer(smaller state after choice) )
    where best is min/max/sum/OR depending on whether the problem says "minimum", "maximum", "number of ways", or "is it possible". The + cost(choice) term is really only for the optimization cases: for min/max you add the choice's cost, but for counting you just combine the sub-answers (ways(state) = ∑ of ways(smaller state)) and for feasibility you OR them (reachable(state) |= reachable(smaller state)) — there is no cost to add.
  5. Find the base cases. The smallest states where the answer is obvious with no choice left (empty amount, empty string, single element, out of bounds).
  6. Pick an evaluation order. Memoization (top-down): write the recurrence as a recursive function + a cache; effortless, matches your derivation. Tabulation (bottom-up): fill an array so every state's dependencies are computed first; needed for space tricks.
  7. Read off the answer. Which state holds the final result? dp[n]? dp[n][m]? max(dp[...])? State it explicitly.

Recipe applied end-to-end: Coin Change (derive, don't memorize)

Problem: coins of denominations {1, 2, 5}, unlimited supply. Use the fewest coins to total A. Let's run the recipe live.

1 — Decision: "which coin do I place right now?" Options: any coin c with c ≤ A.
2 — Last decision: suppose the optimal pile for amount A exists; pull off one coin c. What's left is an optimal pile for amount A - c — the same problem, smaller. (This is the "aha": the leftover is self-similar.)
3 — State: what describes "the leftover"? Just the remaining amount. So dp[a] = fewest coins to make amount a. (Which coins we already placed is irrelevant — that's why amount alone is enough.)
4 — Recurrence: plug into the template "best over choices of (cost + smaller state)". Cost of placing one coin = 1. Smaller state = a - c. "Fewest" ⇒ best = min:

// derived, not memorized:
dp[a] = min over coins c ≤ a of ( 1 + dp[a - c] )

5 — Base case: dp[0] = 0 (zero coins make amount 0). Unreachable amounts = ∞.
6 — Order: dp[a] needs smaller amounts, so fill a from 0 upward (tabulation), or just recurse + cache (memoization).
7 — Answer: dp[A] (or −1 if it's still ∞).

Notice we never "spotted a pattern." We asked the last-decision question and the recurrence fell out. That same interrogation works on LIS ("what is the last element of the increasing subsequence, and what's the best chain ending just before it?"), knapsack ("do I include the last item or not?"), and interval DP ("what is the last thing merged/removed in this interval?").

See it: recursion tree collapses into a memo table (replayable)

When modeling doesn't fall out instantly, pattern-match the surface features of the problem to a family. Each family comes with a ready-made state shape and recurrence skeleton — recognizing the family is often 80% of the modeling.

When it really is a modeling insight (and how to hunt for it)

Be honest: a minority of DPs will not yield to the recipe on the first pass. The choices aren't obvious, or the naive state explodes, or the "subproblem" isn't self-similar yet. That's not a sign you're bad at DP — it's a sign the problem needs a reframing first. Here are the standard moves that manufacture the insight instead of waiting for inspiration.

Heuristics to find the missing model — try them in order:

  1. Sort first. If items have two attributes and comparison feels tangled, sort by one so only the other varies. Russian Doll Envelopes becomes LIS the instant you sort by width. (Watch tie-breaking — sort the second key descending to forbid equal-key chains.)
  2. Think about the LAST element / interval, not the first. "What is the last element of the optimal subsequence?" or "what is the last balloon burst / last stone merged in [l,r]?" Anchoring on the final decision is what makes the leftover self-similar — it's the single most productive question in DP.
  3. Add a dimension to the state. If the recurrence "almost works" but two different histories reaching the same state give different answers, you're missing a fact. Add it: a hold/not-hold flag (stock problems), a remainder mod k, "number of transactions used", "did we place the previous item". The follow-up question a fresh solver would ask is the missing dimension.
  4. Don't pass an accumulator down — bubble it up. Backtracking that carries a running max/sum as an argument can't memoize (same position, different accumulator). Return the sub-answer instead and combine on the way up; the state collapses and memoization turns on.
  5. Transform to a graph / shortest path. "Minimum cost to go from A to B through choices" is often literally shortest path on a DAG (directed graph with no cycles) of states — then topological order (a dependencies-first ordering, where every state comes after the states it needs) is your evaluation order. Coin change is shortest path on 0…A with edges of length 1.
  6. Reframe the objective. Track a difference instead of two quantities (game theory: dp = my score − opponent's); count "ways to fail" and subtract from total; flip "partition into 2 near-equal" into "subset closest to sum/2".
  7. Change what the index means. Index by value instead of position (BIT-accelerated LIS — a BIT, or Binary Indexed Tree, is a structure for fast prefix max/sum queries; see the BIT + DP tab above — or bucket by remainder), or by "number of steps taken" (Cheapest Flights within K stops uses dp[step][node]). The right indexing often shrinks an ad-hoc problem into a template.

Interview move: if you're stuck, say it out loud: "Let me try anchoring on the last decision… if that leftover isn't self-similar, I'll add a dimension or sort first." Interviewers reward a visible method far more than a lucky guess — and running the method usually surfaces the answer within a minute or two.

1D Dynamic Programming

State has one dimension: dp[i] typically represents "the optimal answer considering the first i elements".

Generic Template

int[] dp = new int[n + 1];
dp[0] = base_case;

for (int i = 1; i <= n; i++) {
    for (int choice : choices) {
        dp[i] = Math.max(dp[i], dp[prev] + cost);
    }
}
return dp[n];

Subtype 1: Fibonacci-like (sum of fixed previous states)

// LC 70 Climbing Stairs
// dp[i] = number of ways to reach step i
dp[i] = dp[i-1] + dp[i-2];

// O(n) → O(log n): Matrix Exponentiation
// |F(n+1)| = |1 1|^n * |F(1)|
// |F(n)  |   |1 0|    |F(0)|
// Use fast matrix power (binary exponentiation) for O(log n)
// Applicable to ANY linear recurrence: dp[i] = c1*dp[i-1] + c2*dp[i-2] + ...

Subtype 2: Take-or-Skip (House Robber pattern)

// LC 198 House Robber
// dp[i] = max profit for houses[0..i] (0-indexed, inclusive)
dp[i] = Math.max(dp[i-1], dp[i-2] + nums[i]);
// skip house i  vs  rob house i; base: dp[0]=nums[0], dp[1]=max(nums[0],nums[1])

Subtype 3: LIS-like (enumerate all j < i)

// LC 300 Longest Increasing Subsequence
// dp[i] = length of LIS ending at nums[i]
for (int i = 0; i < n; i++) {
    dp[i] = 1;
    for (int j = 0; j < i; j++) {
        if (nums[j] < nums[i])
            dp[i] = Math.max(dp[i], dp[j] + 1);
    }
}

Subtype 4: Jump-forward (transition from i to i+k)

// LC 1326 Minimum Number of Taps
// dp[i] = minimum operations to cover position i
for (int i = 0; i <= n; i++) {
    for (reachable position j from i) {
        dp[j] = Math.min(dp[j], dp[i] + 1);
    }
}

2D Dynamic Programming

State has two dimensions. Common scenarios: grid traversal, comparing two sequences, or adding a constraint dimension.

Type A: Grid Path

// LC 62 Unique Paths / LC 64 Minimum Path Sum
// dp[i][j] = min cost (or path count) from (0,0) to (i,j)
for (int i = 0; i < m; i++) {
    for (int j = 0; j < n; j++) {
        if (i == 0 && j == 0) dp[i][j] = grid[0][0];
        else dp[i][j] = Math.min(
            i > 0 ? dp[i-1][j] : INF,
            j > 0 ? dp[i][j-1] : INF
        ) + grid[i][j];
    }
}

Type B: Two-Sequence Comparison

// LC 1143 Longest Common Subsequence
// dp[i][j] = LCS length of s[0..i-1] and t[0..j-1]
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (s.charAt(i-1) == t.charAt(j-1))
            dp[i][j] = dp[i-1][j-1] + 1;
        else
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);
    }
}

Type C: 1D + Extra Constraint Dimension

// LC 123 Best Time to Buy and Sell Stock III
// dp[i][k][hold] = max profit at day i, k transactions done, holding or not
dp[i][k][0] = Math.max(dp[i-1][k][0], dp[i-1][k][1] + prices[i]);
dp[i][k][1] = Math.max(dp[i-1][k][1], dp[i-1][k-1][0] - prices[i]);

Space Optimization: Rolling Array

Key idea: If dp[i] only depends on dp[i-1], compress to one row. Reverse iteration order to avoid overwriting needed values.

// Before: dp[i][j] depends on dp[i-1][j] and dp[i-1][j-1]
// After: single array + reverse traversal
for (int i = 1; i <= m; i++)
    for (int j = n; j >= 1; j--)  // reverse!
        dp[j] = dp[j] + dp[j-1];

3D Dynamic Programming

When 2D is insufficient to capture state. Common in: dual-path, multi-operation, or extra-constraint problems.

Type A: Dual-Path (Cherry Pickup)

// LC 741 Cherry Pickup
// Two people walk from (0,0) to (n-1,n-1) simultaneously
// Both walkers have taken `step` moves, so c1 = step - r1 and
// c2 = step - r2 (hence c2 = r1 + c1 - r2) -- 4D state collapses to dp[r1][c1][r2]
for (int step = 0; step <= 2*n-2; step++) {
    for (int r1 ...) {
        int c1 = step - r1;
        for (int r2 ...) {
            // 4 combos: (down,down),(down,right),(right,down),(right,right)
            dp[r1][c1][r2] = max of 4 prev states + cherries;
        }
    }
}

Type B: K Transactions (Stock Series)

// LC 188 Best Time to Buy and Sell Stock IV
// dp[i][k][hold] = day i, k transactions done, holding or not
int[][][] dp = new int[n][K+1][2];
// Base: for every k, day 0 holding = -prices[0] (you bought on day 0).
// Seed this explicitly; leaving holding states at the default 0 lets max()
// keep a bogus 0-cost holding position.
for (int k = 0; k <= K; k++) { dp[0][k][1] = -prices[0]; }
for (int i = 1; i < n; i++) {
    for (int k = 1; k <= K; k++) {
        dp[i][k][0] = Math.max(dp[i-1][k][0], dp[i-1][k][1] + prices[i]);
        dp[i][k][1] = Math.max(dp[i-1][k][1], dp[i-1][k-1][0] - prices[i]);
    }
}

// dp[k][i][j] = ways after k cuts, remaining top-left at (i,j)
// Needs prefix sum to check if sub-region has apples

Knapsack DP

Given a capacity constraint, select items to maximize value. The most classic DP family.

0/1 Knapsack (each item used at most once)

// dp[i][w] = max value using first i items with capacity w
// Transition: take or skip item i
dp[i][w] = Math.max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i]);

// Space-optimized (1D, reverse order)
for (int i = 0; i < n; i++)
    for (int w = W; w >= weight[i]; w--)
        dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);

Unbounded Knapsack (each item unlimited)

// Difference: forward iteration (allows repeated selection)
for (int i = 0; i < n; i++)
    for (int w = weight[i]; w <= W; w++)  // forward!
        dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);

Knapsack Variants

Count ways: dp[w] += dp[w - weight[i]] (not max)
Feasibility: dp[w] = dp[w] || dp[w - weight[i]]
Exactly fill W: init dp[0]=0, rest=-INF
At most W: init all to 0

Common Transformation

Target Sum (LC 494): P - N = target, P + N = sum, so P = (sum + target) / 2. Convert to 0/1 knapsack counting ways with capacity P.

Combinations vs Permutations (Loop Order!)

This is the #1 coin change trap. The two-loop order determines the answer semantics:

// LC 518: How many COMBINATIONS sum to target?
// {1,2} and {2,1} are the SAME → count once
// Coins OUTER, amount INNER:
for (int coin : coins)            // consider each coin in sequence
    for (int j = coin; j <= target; j++)
        dp[j] += dp[j - coin];

// LC 377: How many PERMUTATIONS (ordered) sum to target?
// {1,2} and {2,1} are DIFFERENT → count both
// Amount OUTER, coins INNER:
for (int j = 1; j <= target; j++)  // for each amount, try ALL coins
    for (int coin : coins)
        if (j >= coin) dp[j] += dp[j - coin];

How to never get this wrong (intuition, not memorization):
• Coins outer = "I decide coin1's contribution, then coin2's, then coin3's..." — order of coins is fixed → no duplicate orderings → combinations
• Amount outer = "At each amount, I can pick ANY coin" — so reaching 3 via [1,2] and [2,1] are separate decisions → permutations

Interview phrasing: "If I loop coins outside, I process each denomination in a fixed sequence, so I'll never count choosing coin A after coin B AND coin B after coin A — that gives combinations. If I loop amount outside, at every amount I'm free to pick any coin again, which creates ordered sequences."

String DP

DP on one or two strings. State dp[i][j] usually represents a relationship between s[0..i-1] and t[0..j-1].

Template A: Two-String Comparison (LCS / Edit Distance)

// dp[i][j] = answer for s[0..i-1] vs t[0..j-1]
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++) {
        if (s.charAt(i-1) == t.charAt(j-1))
            dp[i][j] = dp[i-1][j-1] + 1;
        else
            dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]);
    }
}

Template B: Single-String Palindrome (Interval-style)

// LC 516 Longest Palindromic Subsequence
// dp[i][j] = longest palindromic subseq in s[i..j]
for (int i = 0; i < n; i++) dp[i][i] = 1;  // base: single char (len loop starts at 2)
for (int len = 2; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        if (s.charAt(i) == s.charAt(j))
            dp[i][j] = dp[i+1][j-1] + 2;
        else
            dp[i][j] = Math.max(dp[i+1][j], dp[i][j-1]);
    }
}

Template C: Regex / Wildcard Matching

// LC 10 Regular Expression Matching
// dp[i][j] = s[0..i-1] matches p[0..j-1]
if (p.charAt(j-1) == '*') {
    dp[i][j] = dp[i][j-2];  // zero occurrence
    if (match(s, p, i, j-1))
        dp[i][j] |= dp[i-1][j];  // one+ occurrence
} else {
    dp[i][j] = match(s, p, i, j) && dp[i-1][j-1];
}

Interval DP

State dp[l][r] = optimal answer for the interval [l, r]. Enumerate split point k in [l, r-1].

Core Template

// enumerate length -> left endpoint -> split point
for (int len = 2; len <= n; len++) {
    for (int l = 0; l + len - 1 < n; l++) {
        int r = l + len - 1;
        dp[l][r] = INF;
        for (int k = l; k < r; k++) {
            dp[l][r] = Math.min(dp[l][r],
                dp[l][k] + dp[k+1][r] + cost(l, k, r));
        }
    }
}

Recognition Signals

Merge adjacent elements → Stone merge, Matrix chain multiplication
Pop/remove then neighbors merge → Burst Balloons
Operate on both ends → Stone Game
Palindrome (interval shrinks) → Palindrome Partitioning

Tree DP

DP on tree structures. Typically uses post-order DFS — children report results upward.

Core Template

// dp[0] = optimal NOT selecting node
// dp[1] = optimal selecting node
int[] dfs(TreeNode node) {
    if (node == null) return new int[]{0, 0};  // base case: null child contributes {0,0}
    int[] left  = dfs(node.left);
    int[] right = dfs(node.right);

    int[] dp = new int[2];
    // Don't select: children can be either
    dp[0] = Math.max(left[0], left[1])
          + Math.max(right[0], right[1]);
    // Select: children must NOT be selected
    dp[1] = node.val + left[0] + right[0];
    return dp;
}

Template B: All-Pairs Shortest Path (Floyd-Warshall)

// dp[k][i][j] = shortest i->j using first k nodes as intermediaries
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (dp[i][k] != INF && dp[k][j] != INF)   // guard: don't add through unreachable pairs (INF overflow)
                dp[i][j] = Math.min(dp[i][j], dp[i][k] + dp[k][j]);

// LC 787 Cheapest Flights Within K Stops
// dp[step][node] = min cost to reach node using at most `step` edges
// Init all to INF, dp[*][src] = 0. Carry the previous layer forward first,
// otherwise "at most" degrades to "exactly step edges".
for (int step = 1; step <= K+1; step++) {
    dp[step] = dp[step-1].clone();   // reaching v in fewer edges is still valid
    for (int[] edge : flights) {
        int u = edge[0], v = edge[1], w = edge[2];
        if (dp[step-1][u] != INF)   // guard against INF + w overflow
            dp[step][v] = Math.min(dp[step][v], dp[step-1][u] + w);
    }
}

Digit DP

For counting problems: "How many numbers in [L, R] satisfy property X?" Build number digit by digit.

Core Idea

count(R) - count(L-1): Convert range query to "count of numbers ≤ X".
Build digit by digit from MSB to LSB, tracking tight (whether still bounded by upper limit).

Generic Template

// dp[pos][tight][state] -- memoized recursion
int[][][] memo;
String num;  // upper bound as string

// Call with: solve(0, true, true, initialState)  -- leadingZero starts true
int solve(int pos, boolean tight, boolean leadingZero, int state) {
    if (pos == num.length()) return isValid(state) ? 1 : 0;
    // memoize only once digits have started (leading zeros make state ambiguous)
    if (!leadingZero && memo[pos][tight?1:0][state] != -1)
        return memo[pos][tight?1:0][state];

    int limit = tight ? (num.charAt(pos) - '0') : 9;
    int res = 0;

    for (int d = 0; d <= limit; d++) {
        boolean nextLeadingZero = leadingZero && d == 0;
        // still in leading zeros: do NOT fold d into the digit-set / prev-digit state
        int nextState = nextLeadingZero ? state : newState(state, d);
        res += solve(pos + 1,
                     tight && (d == limit),
                     nextLeadingZero,
                     nextState);
    }

    if (!leadingZero) memo[pos][tight?1:0][state] = res;
    return res;
}

Bitmask DP (State Compression)

Use a binary bitmask to represent "which elements have been selected". Works when n ≤ 20.

Core Template

// dp[mask] = optimal answer when selected set = mask
// n elements, 2^n total states
int[] dp = new int[1 << n];
Arrays.fill(dp, INF);
dp[0] = 0;

for (int mask = 0; mask < (1 << n); mask++) {
    int bits = Integer.bitCount(mask);
    for (int j = 0; j < n; j++) {
        if ((mask & (1 << j)) == 0) {  // j not selected
            int newMask = mask | (1 << j);
            dp[newMask] = Math.min(dp[newMask],
                dp[mask] + cost[bits][j]);
        }
    }
}

TSP (Traveling Salesman)

// dp[mask][i] = shortest path visiting cities in mask, at city i
int[][] dp = new int[1 << n][n];
// Transition: from i, go to unvisited j

Submask Enumeration & Partition into k Groups

Classic pattern: split n items into k groups to optimize some per-group cost (LC 2305 Fair Distribution of Cookies, LC 1723, LC 1681). The key primitive is iterating over every submask of a mask.

// Enumerate all non-empty submasks of `avail`
for (int s = avail; s > 0; s = (s - 1) & avail) {
    // s ranges over every subset of avail, largest -> smallest
}

Cost counting. One submask loop over a mask with p set bits runs 2^p - 1 times. Summed over the whole recursion tree (submasks of submasks), the total is 3^n — each bit is independently "not in avail / chosen now / already taken". For n = 8 that is only 3^8 = 6561, so brute force already passes; DP just removes the k factor's blowup.

DP formulation (LC 2305)

// dp[k][mask] = min possible MAX-group-sum when
// distributing cookies in `mask` among k children
// Transition: child k takes submask s, rest go to k-1 children
dp[k][mask] = min over s ⊆ mask of
              Math.max( sum[s], dp[k-1][mask ^ s] );

Why the naive backtracking version can't memoize. If you pass the running max down as a parameter, the state becomes (k, mask, max) — the same (k, mask) reached via different paths carries a different max, so it isn't reusable. Fix: don't pass max down — bubble it up by returning the subproblem's answer and combining with Math.max(sum[s], dfs(k-1, mask^s)). State collapses to (k, mask) and memoization works. This "accumulated-arg → returned-value merge" flip is the general backtracking→DP trick.

Group-sum precompute (no numberOfTrailingZeros)

// Seed single-bit masks straight from the array (index is free)
for (int i = 0; i < n; i++) sum[1 << i] = cookies[i];
// Strip the lowest set bit; source is strictly smaller = already done
for (int m = 1; m < (1 << n); m++) {
    int lb = m & -m;              // lowest set bit (a VALUE, never 0 for m!=0)
    sum[m] = sum[m ^ lb] + sum[lb];  // m^lb zeroes it out, not m&-m
}

Two easy slips: (1) m & -m on a single-bit mask returns itself, not 0 — the value that hits 0 is m ^ lb. (2) No duplicate accumulation: the outer loop assigns (=, not +=) each mask exactly once, and each recurrence strips only the lowest bit, so every bit is added once. Total O(2^n), no Integer.numberOfTrailingZeros needed.

When to Use

n ≤ 20 (2^20 ~ 1M states, acceptable)
Track "which selected/visited"
Permutation assignment: n people → n tasks
Set cover: select fewest subsets to cover universe

SOS DP (Sum over Subsets)

For each bitmask, compute the sum/count over ALL its submasks. Naive = O(3^n), SOS DP = O(n · 2^n).

Problem Statement

Given f[mask] for all masks, compute g[mask] = sum of f[s] for all submasks s of mask (i.e., s & mask == s).

The Key Insight

Process one bit at a time. In iteration i, for each mask with bit i set, add the contribution from the version without bit i. After processing all bits, dp[mask] contains the sum over all submasks.

Template

// SOS DP: dp[mask] = sum of f[s] for all submasks s of mask
int n = 20; // number of bits
long[] dp = new long[1 << n];

// Initialize dp[mask] = f[mask]
for (int mask = 0; mask < (1 << n); mask++)
    dp[mask] = f[mask];

// SOS: process one bit dimension at a time
for (int i = 0; i < n; i++)
    for (int mask = 0; mask < (1 << n); mask++)
        if ((mask & (1 << i)) != 0)
            dp[mask] += dp[mask ^ (1 << i)];

// After this: dp[mask] = sum of f[s] for all s ⊆ mask

Why It Works

Think of each mask as a point in an n-dimensional hypercube. Each iteration "accumulates" along one dimension. After n iterations, every point has accumulated from all its lower neighbors = all submasks.

Loop order matters: Outer loop = bit position, inner loop = all masks. This ensures when we process bit i, all lower-bit contributions are already included. (Same principle as unbounded knapsack's forward iteration.)

Variant: Supermask Sum (invert direction)

// dp[mask] = sum of f[s] for all SUPERmasks s ⊇ mask
for (int i = 0; i < n; i++)
    for (int mask = (1 << n) - 1; mask >= 0; mask--)
        if ((mask & (1 << i)) == 0)
            dp[mask] += dp[mask | (1 << i)];

State Machine DP

Model the problem as states with transitions. Each state represents a "mode" (holding stock, in cooldown, etc). Track the best value for each state at each step.

Core Idea

Define states (e.g., hold, not-hold, cooldown) and transitions between them. At each step, compute each state's optimal value from previous step's states. The answer is the best among final states.

Template: Stock with Cooldown (LC 309)

// States: hold (have stock), sold (just sold), rest (cooldown done)
int hold = -prices[0], sold = 0, rest = 0;

for (int i = 1; i < n; i++) {
    int prevHold = hold, prevSold = sold, prevRest = rest;
    hold = Math.max(prevHold, prevRest - prices[i]);  // keep or buy
    sold = prevHold + prices[i];                       // sell
    rest = Math.max(prevRest, prevSold);               // wait
}
return Math.max(sold, rest);

Template: Stock with Transaction Fee (LC 714)

// Two states: hold, cash (not holding)
int hold = -prices[0], cash = 0;

for (int i = 1; i < n; i++) {
    hold = Math.max(hold, cash - prices[i]);
    cash = Math.max(cash, hold + prices[i] - fee);
}
return cash;

Template: At Most K Transactions (LC 188)

// dp[k][0] = max profit with k transactions, not holding
// dp[k][1] = max profit with k transactions, holding
int[][] dp = new int[K + 1][2];
for (int k = 0; k <= K; k++) dp[k][1] = Integer.MIN_VALUE;

for (int price : prices) {
    for (int k = K; k >= 1; k--) {
        dp[k][0] = Math.max(dp[k][0], dp[k][1] + price);    // sell
        dp[k][1] = Math.max(dp[k][1], dp[k-1][0] - price);  // buy
    }
}
return dp[K][0];

General State Machine Pattern

// LC 1220 Count Vowels Permutation
// States: which vowel is the last character
// Transitions: defined by rules (e.g., 'a' can follow 'e','i','u')
long[] dp = {1,1,1,1,1}; // a, e, i, o, u

for (int step = 1; step < n; step++) {
    long[] next = new long[5];
    next[0] = (dp[1] + dp[2] + dp[4]) % MOD;  // a <- e,i,u
    next[1] = (dp[0] + dp[2]) % MOD;           // e <- a,i
    next[2] = (dp[1] + dp[3]) % MOD;           // i <- e,o
    next[3] = (dp[2]) % MOD;                   // o <- i
    next[4] = (dp[2] + dp[3]) % MOD;           // u <- i,o
    dp = next;
}

BIT (Binary Indexed Tree) + DP

When DP transitions require fast prefix max/sum queries, use BIT or Segment Tree to accelerate from O(n²) to O(n log n).

Core Application: LIS in O(n log n)

// Naive LIS O(n^2): dp[i] = max(dp[j]+1) for j<i, nums[j]<nums[i]
// BIT: use value domain as index, query max dp in [0, nums[i]-1]

int[] sorted = compress(nums);  // map values to [1, n]
BIT bit = new BIT(n);

for (int i = 0; i < n; i++) {
    int val = sorted[i];
    int best = bit.query(val - 1);  // max LIS for values < nums[i]
    bit.update(val, best + 1);     // update LIS at nums[i]
}

BIT Structure

class BIT {
    int[] tree;
    int n;

    BIT(int n) { this.n = n; tree = new int[n + 1]; }

    void update(int i, int val) {
        for (; i <= n; i += i & (-i))
            tree[i] = Math.max(tree[i], val);
    }

    int query(int i) {
        int res = 0;
        for (; i > 0; i -= i & (-i))
            res = Math.max(res, tree[i]);
        return res;
    }
}

When Needed

Pattern: dp[i] = max/min(dp[j]) + ... for j in some range
Brute force: O(n) per transition → O(n²) total
With BIT: O(log n) per transition → O(n log n) total

Monotone Stack / Deque Optimization

When DP transitions involve sliding-window max/min, use a monotone deque for O(1) amortized access.

Monotone Deque Template

// dp[i] = min(dp[j] + cost(j,i)) for j in [i-k, i-1]
Deque<Integer> deque = new ArrayDeque<>();
dp[0] = base_case;      // seed the base state...
deque.offerLast(0);        // ...and push it, so peekFirst() is never called on an empty deque

for (int i = 1; i < n; i++) {
    // Remove indices that fell out of the window [i-k, i-1]
    while (!deque.isEmpty() && deque.peekFirst() < i - k)
        deque.pollFirst();

    // Transition: deque front is the optimal (minimal-dp) j in window
    dp[i] = dp[deque.peekFirst()] + cost;

    // Maintain increasing-dp monotonicity before pushing i
    while (!deque.isEmpty() && dp[deque.peekLast()] >= dp[i])
        deque.pollLast();
    deque.offerLast(i);
}

Monotone Stack: Largest Rectangle

// LC 84 Largest Rectangle in Histogram
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i <= n; i++) {
    int h = (i == n) ? 0 : heights[i];
    while (!stack.isEmpty() && heights[stack.peek()] > h) {
        int height = heights[stack.pop()];
        int width = stack.isEmpty() ? i : i - stack.peek() - 1;
        maxArea = Math.max(maxArea, height * width);
    }
    stack.push(i);
}

Probability DP

State represents a probability or expected value. Transitions multiply/divide by probability of each event. Use double[] or track fractions.

// dp[r][c] = probability of being at (r,c) after k moves

}
// Sum all dp[i][j] = total probability of staying on board

Template: New 21 Game (LC 837)

// dp[i] = probability of reaching score exactly i
// Draw uniformly from [1, maxPts], stop when score >= k
// REQUIRED guard: if k==0 (no draws) or n >= k+maxPts, every reachable
// score is <= n, so answer is 1.0. Without it the window subtraction below
// removes dp[i-maxPts] values that were never added (i-maxPts >= k) => wrong.
if (k == 0 || n >= k + maxPts) return 1.0;

dp[0] = 1.0;

    dp[i] = windowSum / maxPts;
    if (i < k) windowSum += dp[i];   // still drawing
    if (i >= maxPts) windowSum -= dp[i - maxPts];
}
// Answer = sum(dp[k..n])

Game Theory DP (Minimax)

Two players take turns. Each plays optimally. Determine winner or optimal score difference.

Template: Stone Game (LC 877 / Predict the Winner 486)

// dp[i][j] = max score difference (current player - opponent) for piles[i..j]
for (int len = 1; len <= n; len++) {
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        if (len == 1) dp[i][j] = piles[i];
        else dp[i][j] = Math.max(
            piles[i] - dp[i+1][j],   // take left
            piles[j] - dp[i][j-1]    // take right
        );
    }
}
// First player wins if dp[0][n-1] >= 0 — tie (0) goes to P1 in Predict the Winner (LC 486); in Stone Game (LC 877) ties are impossible so > 0 also works

Template: Minimax with Memoization

// LC 464 Can I Win / LC 1728 Cat and Mouse II
Map<Integer, Boolean> memo = new HashMap<>();

boolean canWin(int state) {
    if (memo.containsKey(state)) return memo.get(state);

    for (each possible move) {
        int nextState = applyMove(state, move);
        if (isWin(nextState) || !canWin(nextState)) {
            memo.put(state, true);
            return true;  // current player can force a win
        }
    }
    memo.put(state, false);
    return false;
}

Key Insight: Score Difference Trick

Instead of tracking both players' scores separately:
dp[state] = (current player's score) - (opponent's score from remaining game).
When current player takes value V: dp = V - dp[next_state].
This works because opponent's best = our worst, and vice versa.

for (int i = 1; i <= n; i++)
    for (int coin : coins)
        if (i >= coin) dp[i] = Math.min(dp[i], dp[i - coin] + 1);
// answer: dp[n] > n ? -1 : dp[n]

// TOP-DOWN (recursive) — exact same logic, different structure:
int[] memo = new int[n + 1];
Arrays.fill(memo, -1);

int solve(int amount) {
    if (amount == 0) return 0;
    if (amount < 0) return Integer.MAX_VALUE;
    if (memo[amount] != -1) return memo[amount];
    int res = Integer.MAX_VALUE;
    for (int coin : coins) {
        int sub = solve(amount - coin);
        // GUARD: sub == MAX_VALUE means unreachable; sub + 1 would overflow to MIN_VALUE
        if (sub != Integer.MAX_VALUE) res = Math.min(res, sub + 1);
    }
    return memo[amount] = res;
}

2D → 1D Space Optimization (Common Follow-up)

"Can you reduce space from O(mn) to O(n)?"
If dp[i][j] only depends on dp[i-1][...], keep only one row. Check dependency direction to decide iteration order.

// 2D version: O(m*n) space
int[][] dp = new int[m+1][n+1];
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++)
        dp[i][j] = dp[i-1][j-1] + 1;  // depends on prev row

// 1D version: O(n) space — iterate j in REVERSE if depends on dp[i-1][j-1]
int[] dp = new int[n+1];
for (int i = 1; i <= m; i++)
    for (int j = n; j >= 1; j--)  // REVERSE to avoid overwriting!
        dp[j] = dp[j-1] + 1;

// Rules:
// - Depends on dp[i-1][j] and dp[i-1][j-1] → reverse j
// - Depends on dp[i][j-1] (same row, left) → forward j is fine
// - Depends on both → need a "prev" variable to save dp[j-1] before overwrite

Advanced: Knuth's Optimization

Reduces interval DP from O(n³) to O(n²) when optimal split is monotone. Applies to LC 1547 (Cut Stick). Rarely relevant to standard coding interviews, but useful for competitive programming.

Common Pitfalls

Missing base case: dp[0] = ? Often 0 or 1, think carefully.
Wrong iteration order: 0/1 knapsack reverse; unbounded forward.
Ambiguous state: "first i items" vs "ending at i" — huge difference!
Integer overflow: Counting problems need mod 10^9+7.
Boundary: i-1 < 0? j-weight < 0? Always check.
